# Deployment smoke scenario resources

This is an incomplete, synthetic installation diagnostic, not an operational
forecast configuration or a runnable deployment. The packaged station-supported
discharge fixture has passed pure Stage 1 QC qualification. Normal loader/QC
integration and worker/API evidence remain pending in the manifest.

`discharge_hourly.csv` and `scenario.json` are exact-byte copies of the generic
station team's fixtures from commit `3ea1c2ec752faf916e8aa64023a6190cb0b7ec65`
(PR #554), under `tests/fixtures/synthetic_station/`. The source README records the
seeded recession/storm generator and its provenance. No generator runs here.
The station is `SYN001`, network `synthetic`, with synthetic coordinates and UTC
timezone; the disposable `smoke` tenant is supplied separately at setup.

The CSV has 72 contiguous hourly UTC observations in m³/s, from
`2024-12-31T00:00:00Z` through `2025-01-02T23:00:00Z`. Tests parse the actual CSV
timestamps. `qc-rules.toml` pins the existing hourly discharge rules from the
source revision's built-in rule set in the normal loadable configuration format.
This explicit snapshot avoids inheriting agency configuration. Tests run the real
`Stage1QualityChecker.check_with_coverage` with no overrides or baselines:

| Rule | Readings judged | Flags |
| --- | ---: | ---: |
| range_check (0–100000 m³/s) | 72 | 0 |
| rate_of_change (max_rate 50) | 71 | 0 |
| spike (tolerance 0.75) | 70 | 0 |
| gross_outlier (k_sigma 5) | 0 | 0 |

All 72 readings are judged by at least one rule. Rate needs a predecessor and
spike needs both neighbours. Gross outlier is unavailable without a climatology
baseline; hourly frozen-sensor detection is not configured. Zero flags do not
establish database `GOOD` status: the merged observation loader currently stores
raw observations, and its QC integration remains a separate dependency.

The fixed cycle is `2025-01-03T00:00:00Z`. Weather contains one control member (`0`)
with precipitation in mm for the three future hours. The `icon_ch2_eps` source tag
uses existing internal routing; all weather is synthetic and no provider is called.
UTC is this diagnostic's explicit time choice, not an agency display default.

The pure model requires three hourly discharge observations ending one hour before
the cycle and precipitation at cycle +1, +2 and +3 hours. For member `m` from 0 to
19 it returns `Q_last + precipitation_factor * P + member_increment * m`.
FI trajectory columns are numbered `1` through `20`. Output starts two hourly steps
after the final observation, with three steps and units m³/s. These deterministic
values carry no scientific skill; the model is explicitly supplied, never globally
registered for operational use.

`expected-result.json` pins all 60 expected discharge values using independent
decimal arithmetic and the source's final reading, `19.737592`. First-member values
are `19.837592, 19.937592, 20.137592`; last-member values are
`20.027592, 20.127592, 20.327592`. Tests compare the real weather assembly and FI
adapter output against this oracle; no expected value is generated by `predict`.
These are numerical expectations, not evidence of runtime health or API delivery.

`model-config.json` owns the exact-byte configuration hash. `artifact.json` stores
the matching deterministic artifact; `manifest.json` pins the resource hashes.
Read resources using `importlib.resources.files("sapphire_flow")` and the relative
path `data/deployment_smoke/`; they are packaged in the wheel independently of tests.

Tests exercise real FI input/output adaptation and the configured operational
ensemble-size floor with correctly timed inputs. Generic model-onboarding helper
qualification remains unavailable: its generated prediction inputs reuse historical
timestamps for future weather and set issue time to the final observation. The
model's declared future grid and coverage checks remain strict. The planned audited
artifact-import path does not require those helper-generated prediction inputs.

Runtime commands, worker/API proof and administrator instructions belong to later
milestones in `docs/plans/deployment-hello-world.md`.
