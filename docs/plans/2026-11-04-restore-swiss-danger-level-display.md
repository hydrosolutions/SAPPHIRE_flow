## Exact additive wire contract
Add optional `series` on `CmalAvailable` only. No other headline variant gains it.
It is NOT in the generated OpenAPI required list; nullable compatibility is allowed,
while the new route always supplies one of the explicit variants below. Assert
requiredness in the backend contract test. An older response may omit it or contain
null; a new frontend treats either as
series unavailable without discarding the headline or overview. The new backend
explicitly produces one of these two shapes:

```json
{"state":"available","time_step_seconds":86400,"quartile_method":"stored_quantiles","points":[["2026-11-04T00:00:00Z",100.0,90.0,110.0],["2026-11-05T00:00:00Z",120.0,105.0,135.0]]}
```

```json
{"state":"unavailable","reason":"point_limit"}
```

- Available point order is `[valid_time, median, p25, p75]`. UTC timestamp strings
  represent interval STARTS, preserving actual source times; no shared-grid assumption
  or positional alignment across members. The tuple order is fixed in OpenAPI and
  example/parser tests. Frontend Ajv 6 only checks the compatible envelope, not
  OpenAPI 3.1 `prefixItems`; prove tuple order/types with native backend schema
  assertions and direct frontend parser negative tests, not a vacuous Ajv tuple test.
  Unit and output identity are inherited from the containing
  headline; no duplicated identity, model or threshold fields.
- `time_step_seconds` is finite and positive. Each point covers
  `[valid_time, valid_time + time_step_seconds)`. Points are strictly increasing and
  unique. First point equals headline horizon_start; last point plus step equals
  horizon_end. Only the same still-eligible intervals as the headline are included.
- Between 1 and 10 points, covering the existing daily ten-step benchmark and actual
  five-step CMAL runs. More points produce `point_limit`, never truncation; headline
  remains unchanged. A 72-hourly-point stress candidate therefore retains its headline
  but has explicit series unavailability. This is not an extension of forecast horizons.
- Median is finite; p25/p75 are finite or null. Missing stored quartiles stay null.
  Present bounds must satisfy p25 <= median <= p75; inconsistent/nonfinite supplied
  bounds produce `invalid_series`, not invented values. Any nonfinite source value
  in a retained timestamp group invalidates the series, even if the pre-existing
  headline computation happens to yield a finite median. Duplicate stored 0.25, 0.5
  or 0.75 levels at a retained time also produce `invalid_series`. Do not pick an
  arbitrary duplicate or filter nonfinite members to improve the record. Preserve
  the existing headline; fixing its separate nonfinite-median weakness is out of scope. Null bounds mean missing
  uncertainty, never a zero-width band. Member-derived quartiles need five finite
  members at the timestamp, per T2. `quartile_method` is `stored_quantiles` or
  `member_empirical_type7`; label derived bands as computed by the backend, not the map.
- Unavailable series reasons are `point_limit` and `invalid_series`. They are
  component-local. A malformed/unknown series in a response is also local unavailability
  in the frontend, with a visible no-curve/no-trend reason; no stricter whole-overview
  failure. Publication-withheld and unavailable HEADLINES never emit series.
- No rounding: preserve binary64 numeric round-trip values. Enforce the approved
  393216-byte raw UTF-8 body limit in the Swiss reader before JSON parsing (not merely
  a character count or compressed Content-Length). Replace its current 2000000 guard
  with a clearly byte-named constant. Use existing streamed byte counting and also
  check UTF-8 bytes for non-stream/test-double text responses locally in the Swiss
  reader; do not change other readers' limits or shared helper semantics. Test exactly
  393216 and 393217 bytes, multibyte text, and missing/misleading Content-Length.
  An oversized answer remains an explicit unavailable read, never truncated JSON.
  Actual full-roster native response benchmarking must fit the same approved limit. Read-only size estimates:
  saved 134-station envelope 232128 bytes; with 132 real five-step private CMAL series
  in this shape 299736 bytes; synthetic ten-step extension 353484 bytes. These estimates
  combine a November 4 envelope and November 3 values for size ONLY, not a scientific
  response or deployed benchmark. Qualify real integration responses before release.
