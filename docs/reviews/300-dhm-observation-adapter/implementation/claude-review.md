Smallest fix: replace `**Plan 300 (DRAFT)**` with `**Plan 300 (COMPLETE, archived)**` and link `archive/300-dhm-observation-adapter.md`.

### Low 2 — the approved plan's T3 verification command was edited, not just annotated
`docs/plans/archive/300-dhm-observation-adapter.md:388-390` adds `tests/unit/flows/test_ingest_observations_dhm.py` to the one-shell-command verification. The approved READY revision (`aa50f886`, plan lines 377-378) named only `tests/unit/config/ tests/unit/adapters/test_dhm.py tests/unit/flows/test_ingest_observations.py`. Under `docs/workflow.md` § Human authority, the implementer runs the plan's verification and records results; changing a READY plan's requirement text is the owner's call. Smallest fix: restore the approved command line and record the added module in the T3 "Implemented and verified" note as a deviation. (Everything else in the archived plan is unchanged from the approved text apart from `status:`, archive-relative links, the Review-and-exit-gates paragraph, and the three implementation notes.)

### Low 3 — "skipped without an outcome" is not actually asserted
`tests/unit/flows/test_ingest_observations_dhm.py:218-227`. Plan T3 Verification requires the WEATHER station be "skipped without an outcome". The assertions (`observations_stored`, `stations_failed`, `len(requests)`, health status, `failure_counts_by_cause`) are all satisfied equally if the WEATHER and foreign-network stations returned *clean* outcomes — only a *failed* outcome would be caught. Smallest fix: add `assert record.detail["stations_polled"] == 1 + int(include_unbound)`.

### Low 4 — T2's "both public protocol methods produce consistent observations/outcomes" is not tested
`tests/unit/adapters/test_dhm.py:80` is the only `fetch_observations` call; every other test uses `fetch_observations_batch`. No test compares the two on the same input. Consistency holds by construction (`adapters/dhm.py:81` delegates), so the risk is nil, but the named verification item is unmet. Smallest fix: in `test_captured_day_preserves_every_value_and_timestamp`, also call `fetch_observations_batch` and assert `actual == batch.observations`.

### Low 5 — `CONFIGURATION_ERROR` is used for a case outside its documented meaning
`src/sapphire_flow/adapters/dhm.py:122-123` maps a missing `since` entry to `FetchOutcomeCause.CONFIGURATION_ERROR`. Plan D7 and `docs/spec/types-and-protocols.md:262` define that cause as a supported DHM gauge lacking valid binding/level metadata. A missing watermark is a caller error, not station configuration. Unreachable on the scheduled path (`flows/ingest_observations.py:664-667` populates `since` for every eligible station), but reachable from the supervised-recovery call shape documented in `docs/requirements/dhm-api-examples/README.md`. Smallest fix: extend the `types-and-protocols.md:262` comment to include "or a caller-supplied watermark is absent".
